# NextStep Lab — запуск и деплой

Эта инструкция рассчитана на первый опыт публикации сайта. **Для базовой версии не нужны платные сервисы, API-ключ, установка npm-пакетов или база данных.**

## 1. Проверка на своём компьютере

1. Скачай архив `NextStep_Lab.zip` и распакуй его.
2. Найди папку `nextstep-career-lab`. Внутри должны лежать `index.html`, `app.mjs`, `styles.css`, `data.mjs` и другие файлы.
3. Открой терминал **в этой папке**:
   - macOS: в Terminal напиши `cd ` (с пробелом), перетащи папку `nextstep-career-lab` в окно Terminal и нажми Enter.
   - Windows: открой папку в Проводнике, напиши `cmd` в адресной строке и нажми Enter (или открой папку в VS Code и выбери Terminal → New Terminal).
4. Запусти локальный сервер.

**macOS / Linux:**

```bash
python3 -m http.server 8000
```

**Windows:**

```powershell
py -m http.server 8000
```

Если Python отсутствует, установи Python 3 с https://www.python.org/downloads/ и повтори запуск. Можно воспользоваться расширением VS Code Live Server вместо Python.

5. Открой в браузере: **http://localhost:8000**.
6. Проверь по порядку:
   - «Подставить пример» → «Сравнить направления»;
   - нажать на другое направление в отчёте;
   - «Сохранить план» → «Мои планы» → отметить задание;
   - перезагрузить страницу: сохранённый план должен остаться;
   - скачать отчёт в TXT;
   - открыть «Как это работает».
7. Для остановки сервера нажми **Ctrl+C** в терминале.

**Важно:** не запускай сайт двойным нажатием по `index.html`: ES-модули могут не загружаться по `file://`.

## 2. Загрузка проекта на GitHub

GitHub — место хранения исходного кода и удобный способ синхронизировать его с хостингом. Для публичной ссылки на сайт нужен отдельный шаг в разделе 3.

### Вариант А: через сайт GitHub (без команд Git)

1. Войди в https://github.com/ или зарегистрируйся.
2. Выбери **New repository** → название `nextstep-career-lab` → **Public** или **Private** → **Create repository**.
3. В пустом репозитории выбери **uploading an existing file** или **Add file → Upload files**.
4. Перетащи **содержимое** локальной папки проекта, включая файлы в `api/` и `tests/`. Если сайт не переносит папки корректно, используй вариант Б ниже или GitHub Desktop.
5. Проверь структуру: `index.html` должен лежать в **корне репозитория**, а не в дополнительной вложенной папке.
6. **Никогда не публикуй `.env`, реальные ключи или личные данные.** Файл `.env.example` безопасен: в нём только названия переменных.
7. Нажми **Commit changes**.

### Вариант Б: через терминал и Git

Сначала создай **пустой** репозиторий на https://github.com/new, без первоначального README. В папке проекта выполни:

```bash
git init
git add .
git commit -m "Add first working prototype"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/nextstep-career-lab.git
git push -u origin main
```

Замени `YOUR_USERNAME` на свой логин GitHub. При необходимости GitHub попросит войти в аккаунт. Если `git` отсутствует, установи его с https://git-scm.com/downloads или используй GitHub Desktop.

## 3. Публикация на Vercel (рекомендовано)

1. Войди в https://vercel.com/ (можно использовать GitHub-аккаунт).
2. Выбери **Add New → Project** или **New Project**.
3. Подключи GitHub и выбери репозиторий `nextstep-career-lab` → **Import**.
4. В настройках проекта:
   - **Framework Preset:** `Other` (если Vercel не выбрал автоматически).
   - **Root Directory:** `./` (корень с файлом `index.html`).
   - **Build Command:** не нужен, потому что сайт статический.
   - **Output Directory:** оставь настройку по умолчанию для проекта без сборки. Если интерфейс требует путь, проверь, что публикуются файлы из корня репозитория.
5. Нажми **Deploy**.
6. После завершения Vercel покажет адрес формата `https://имя-проекта.vercel.app`. **Это твоя настоящая публичная ссылка**; пример адреса здесь не является активным сайтом.
7. Открой адрес в приватном окне браузера или на телефоне и повтори базовый тест из раздела 1.

При последующих изменениях кода достаточно загрузить коммит в GitHub: подключённый Vercel создаст новый деплой. См. [официальную документацию Vercel](https://vercel.com/docs/git).

### Если после деплоя белый экран или 404

- Проверь, что `index.html` находится в корне импортированного репозитория.
- Проверь **Root Directory**.
- Убедись, что файлы `app.mjs`, `engine.mjs`, `data.mjs` и `styles.css` лежат рядом с `index.html`.
- Открой инструменты разработчика браузера (Console/Network) и проверь ошибки загрузки.
- Не задавай случайную директорию сборки (`dist`, `build`) — в этом проекте её нет.

## 4. Опционально: реальный AI-комментарий

Это **не обязательный шаг**. Весь основной сценарий работает локально без AI API. Если хочешь, чтобы кнопка «AI-комментарий» действительно генерировала текст, понадобятся аккаунт AI-провайдера и возможные расходы на API (подписка ChatGPT не включает API-оплату).

1. Создай персональный API-ключ на https://platform.openai.com/ и установи ограничения расходов в кабинете провайдера.
2. Открой Vercel → свой проект → **Settings → Environment Variables**.
3. Добавь следующие **серверные** переменные:

   | Название | Значение |
   |---|---|
   | `OPENAI_API_KEY` | твой секретный API-ключ |
   | `DEMO_ACCESS_CODE` | длинный случайный код, который знаешь только ты и выбранные тестировщики |
   | `OPENAI_MODEL` | например, `gpt-4.1-mini`, если доступна для твоего API-аккаунта |

4. Не добавляй эти значения в `index.html`, `app.mjs`, GitHub или `.env.example`.
5. Сделай **Redeploy** после изменения переменных (например, в Vercel → Deployments → меню последнего деплоя → Redeploy).
6. На опубликованном сайте заполни профиль, получи результат, нажми «AI-комментарий». Введи `DEMO_ACCESS_CODE` в появившееся окно.

**Безопасность:** пароль демонстрационного стенда не равен полноценной системе доступа, защите от перебора или rate limiting. Для открытого публичного AI-сервиса нужны серверное ограничение запросов, мониторинг стоимости, аутентификация и контроль обработки данных. Пока этого нет, **не раздавай код доступа публично** и используй основной режим без API.

**Локально команда `python3 -m http.server` не запускает Vercel Functions**, поэтому на `localhost:8000` AI-комментарий не сработает. Для локальной проверки серверной функции нужен Vercel CLI и настроенное окружение (см. https://vercel.com/docs/cli).

Документация по переменным окружения и обязательному передеплою: https://vercel.com/docs/environment-variables/managing-environment-variables

## 5. Альтернатива: GitHub Pages (без AI)

Если не нужна серверная функция, можно опубликовать бесплатную статическую версию:

1. В GitHub открой репозиторий → **Settings → Pages**.
2. В **Build and deployment → Source** выбери **Deploy from a branch**.
3. Укажи ветку `main`, папку `/(root)`, нажми **Save**.
4. После публикации ссылка будет примерно `https://YOUR_USERNAME.github.io/nextstep-career-lab/`.
5. Проверь работу сайта по этому адресу. Вкладки, планы и расчёт должны работать. **AI-комментарий через `/api/coach` на GitHub Pages не работает** (там нет серверной функции).

Официальная инструкция GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 6. Перед тем как показать проект другим

- Проверь текст без навыков и с коротким описанием.
- Убедись, что на телефоне видны все кнопки и разделы.
- Проверь сохранение плана после перезагрузки.
- Проверь, что сайт не содержит настоящих API-ключей и персональных данных.
- Не представляй учебные проценты как точность AI или статистику реальных пользователей.
- Показав проект, описывай его как личный эксперимент, а не как внедрённый или уже проверенный продукт.
